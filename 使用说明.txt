ROM 规则合并 1.0.5

这是手机上的 root APK，不是刷机包。
第一栏填你要补的 ROM 解包目录，第二栏填提供规则的 ROM 解包目录。
例如 /data/DNA/DNA_AA 和 /data/DNA/DNA_BB。填的是目录，不是 img，也不是某一个 cil。
不要选正在运行的 /system、/vendor 或模块目录。两个目录不能相同，也不能互相包含。
支持 system/system/etc/selinux 和 system/etc/selinux 两种常见 system 解包结构。
目标必须有完整的平台 CIL、对应 mapping 和 vendor。来源可以只有 vendor/odm，不必为了检测通过而复制一套 system；来源仍须有有效 plat_sepolicy_vers.txt 和 vendor 主 CIL，所有引用按目标实际策略检查。

你点“开始修改”后，它会先做快照，合并后完整编译，成功才备份并写回第一栏的原文件。
第二栏只读。不会刷镜像，不会重启，不会给当前运行的内核注入策略。
处理范围是 system、system_ext、product、vendor、odm 的 SELinux 文件。ODM 有规则就处理，没有独立 CIL 就处理已有的上下文缓存。
OTA 结构请勾选“OTA 模式”：强制只写 vendor/odm，system/system_ext/product 只读参与编译。来自平台分区的新增规则会尝试放进可承载该变体的已有 vendor CIL，新增标签放进 vendor/odm 已有的同类正式 contexts；没有合适文件会明确报告，不能凭空生成一个 init 不读取的文件。OTA 模式下旧二进制缓存也只在 vendor/odm 范围内移出。
高级设置可勾选“只生成候选并验证”：保存候选、编译结果和诊断，目标不写回、不移出缓存，也不生成恢复事务。关闭它后需重新开始任务才会写回。
打包、刷入和开机测试仍由你自己做。

高级设置里可以通过文件选择器补充 sepolicy.rule 或基础 TE 规则。
额外规则的类型、对象类、权限也交给统一筛选。比如 binder 类没有 ioctl，只排除这个无效权限；同条规则的 call、transfer 等有效权限仍保留，不会因此终止整个合并。
TE 的 m4 宏、整份 policy.conf、Magisk deny/enforce 不在这版支持范围，碰到不认识的额外指令会报错，不会假装全部合上。
勾选当前手机作为来源，只读取 /system、/system_ext、/product、/vendor、/odm 各自 etc/selinux 下的 CIL、mapping、版本文件和正式 contexts。
不读取 /sys/fs/selinux/policy，不导出运行时二进制，不收集 KernelSU、Magisk、模块动态注入内核的规则。也不读取模块目录下的 sepolicy.rule。
分区来源与第二栏 ROM 一样处理，优先按分区归属合入。目标缺对应 CIL 时回落到 vendor；有独立普通/debug 策略时，共用文件的新增会放入该变体独立的 CIL（优先 vendor），避免只在普通或 debug 存在的类型串到另一套策略。
来源中已选用的分区缺少必需的 CIL 或 mapping 会停止；允许来源整体缺少 system，但不借用手机平台或导出内核补齐它。手机分区文件的来源路径和哈希保存在任务的 device-partitions.json，副本在 device-partitions 目录。
注意，读取的是分区当前可见文件。如果你用了模块直接覆盖分区 CIL，或者 ROM 本来就含有 root 规则，这种静态文件内容仍会读到，不是假装它们一定来自官方原包。
如果以前用 1.0.0 到 1.0.2 勾选过本机来源并成功写回，先恢复那次合并前的备份，再用新版重新合并。更新 APK 或在旧结果上再跑一次，都不会自动删除已混入的运行时规则。不要按 ksu 这个名字盲删，以免漏掉其他注入规则或破坏引用。
尽量预留 2GB 以上内存，处理时别同时打包大型镜像。任务结束后不会留下常驻守护进程。
1.0.2 改为优先使用系统自带的独立 ART 启动 root 工作进程，绕开 app_process 被系统 prop 限回 512MB 的情况。不改全局 dalvik prop，不影响其他应用。
工作进程按当时可用内存选择 Java 堆上限，最多 1536MiB，不是启动就占满这么多。手机空闲内存少时会降低；系统实际内存用尽或原生编译器内存不足，仍可能失败，并不是无限内存。
启动日志会同时显示申请值和实际堆上限。没有独立 ART 的系统会提示回退 app_process，并显示实际限制，不假装解除成功。
额外规则解析改成只读使用已有索引，不再复制几十万条完整规则。CIL 短字符串复用，构建索引逐条消费，contexts 检查只保留类型信息；这些优化不靠裁掉有效 allow 来省内存。
第二栏、额外文件和当前手机都是来源，都走筛选和完整编译，不存在免检来源。

1.0.5 默认开启“向 debug 补齐普通 vendor/odm 规则”。会读取来源普通版，以及目标当前普通版已经合入的小米等补丁，将能被 debug 接受的声明、属性、角色和权限一并补入。不会仅为了标签通过而伪造空 type，也不把 debug 专用规则反向加给普通版；system/system_ext/product 的变体规则仍隔离。
这修复了“候选里明明有 type，为什么还报缺失”的主要原因：普通版声明不代表 debug 编译输入也包含它；有声明也不代表最终二进制中的角色、MLS 上下文一定有效。
自动编号属性按文件及其成员定义区分，避免不同来源 ROM 的 base_typeattr 等同名属性被错误混合。相同输入重复合并不应继续追加同一批自动属性，目标普通版向 debug 补齐也采用稳定标识。
来源 CIL/contexts 的实际读取副本保存于任务 source，额外规则保存为 extra-snapshot.rule，便于重现；不读取来源后再偷偷补写来源文件。复用已有快照或事务的任务目录会被拒绝，避免覆盖旧备份。

这版按你的要求保留宽权限。不会因为 allow 权限大，或者触犯 neverallow，就把它裁掉。
所有来源的新 neverallow、neverallowx、dontaudit、dontauditx 都不导入。
TE/Magisk 里的 neverallowxperm、dontauditxperm 也是这样处理。
目标本来就有的断言和 dontaudit 保留，编译加 -N 跳过 neverallow 检查。
来源已有的域宽容可以导入，但不新增 init、vendor_init、ueventd 宽容。

标签会尽量合并，包括 property_contexts、file_contexts、服务上下文、seapp 和 genfscon。
contexts 同一个匹配键冲突时，system、system_ext、product 优先于 vendor、odm，后两者的冲突项删除，文本预编译 contexts 缓存也同步平台标签。每项处理都写进日志。
这个优先级适用于目标原有冲突和各来源导入后的冲突。只处理相同匹配键，不猜测不同正则是否重叠，文件类型限定和属性 exact/prefix 不同也不会混删。相同标签无需改动。同一侧仍保留目标或先合入项；平台侧多条互相冲突、无法裁决时停止写回。
如果目标原本的属性前缀已经冲突，或者标签引用的类型根本不存在，会停止写回，让你看日志。
ODM/vendor 的 precompiled_*_contexts 是派生文本缓存，会补上新键，清掉其中已经没有类型定义的失效旧标签；正式 contexts 不这样随便删。
编译器明确发现新增转换冲突时，可以只撤下对应新增转换重试，不借机删除 allow。
发现无法准确处理的编译错误就停止，不能把“删到编过”为目标。

验证不是开机保险。
目前会做 AST/符号和上下文冲突检查、完整 split CIL 的普通版与 debug 版编译、二进制读写回读、上下文类型/角色检查。
核心验证器是从 AOSP Android 17 正式源码构建的 secilc 和 libsepol 小工具，不是把不认识的新能力删掉再编。
这版没有把二进制回读冒称为 magiskpolicy 验证，也没有执行 --live。
正则初筛不等于完整 PCRE2/checkfc 验证。文件标签的硬件语义、服务匹配和实际开机问题仍要真机确认。
遇到未支持的嵌套 CIL、宏或命名结构会记在内部审计里，不能说全世界任何 CIL 都能无损合并。

不是只支持澎湃或 Android 17。
APK 最低 Android 9，当前发布 ARM64 版本，需要 root。
合并按目标 ROM 的 split policy、对象类、权限和 mapping 判断，不用品牌白名单。
30.0、33.0 这类旧接口版本，以及 202404、202504 这类日期版本都有对应处理。
来源的版本化引用只在确认目标符号存在时适配，不全局改目标后缀，不改 plat_sepolicy_vers.txt，不改 SDK prop。
自动编译版本优先读取目标预编译策略，没有可读缓存时用 33 并提示；旧内核可以在高级设置手选 26 到 33。
注意这个二进制版本不是 Android 版本，也不是 mapping 版本。不要听到“改 37”就随便填。
跨版本兼容是这版的设计目标，不代表 Android 9 到 17 每个厂商、每个内核都已经实测。

点击“保存日志”可以把日志保存成 txt，里面有任务结果、contexts 冲突、跳过/筛选/转换冲突详情及 normal/debug 诊断。
validation.json 分别记录两套策略的实际 CIL 输入、编译阶段、回读结果和去重标签数量；若两套输入相同，只验证一次。contexts-invalid-normal.json 或 contexts-invalid-debug.json 标出失败变体、标签、所在文件和行号，以及两套候选各自是否声明该 type。声明检查是线索，最终以编译后二进制的校验结果为准。
summary.json 在成功或失败时保留已有统计和设置，audit.jsonl 保存逐条依据。界面明确显示跳过和筛选数量；“验证通过”不等于来源每一条都已合入。EXCLUDED 代表按既定规则排除的断言/dontaudit 等，SKIPPED 代表未导入项，FILTERED 代表无效权限处理，COMPILER_CONFLICT 代表自动撤下的冲突新增转换。这些记录按处理事件计数，可能同时包含普通/debug，不能直接当成唯一规则数量。
页面有固定高度的实时日志框，可以在框内上下滑动。手动滑动时暂停自动跟随，按“回到最新”继续跟随。
编译阶段会实时输出中文进度和运行心跳，不用等编译结束才看到日志。无法翻译的编译器原始诊断会保留。
窗口最多显示最近约 64KB 合并日志和 32KB 恢复日志，保存日志仍可导出完整记录。
逐条 CIL 审计不在导出的日志里刷屏，完整审计、编译输出和备份在页面显示的任务目录。
备份在 APK 私有目录，卸载 APK 或清除应用数据会一起丢掉。正式刷入前，把备份另存一份。
写回失败会尝试恢复；如果你或其他工具在此期间改了同一个文件，会拒绝盲目覆盖，请停下来查看 transaction.json。
文件是逐个原子替换的，不是整个 ROM 跨文件原子事务。断电后要查看记录并恢复，不能直接拿半成品打包。1.0.5 在写入和恢复前记录准确的暂存路径，恢复时清理本次事务留下的半写临时文件；不会扫描通配符并删除其他工具的文件。旧版未记录的临时文件不会被自动认领。
有变化时，写入范围内旧 precompiled_sepolicy 和 debug 缓存会从目标移除并留备份，让 ROM 按新 split CIL 编译；临时验证的 policy 二进制不会当 ROM 成品写进去。
只向已有的策略文件追加，不为缺失分区凭空生成挂载和打包配置，也不会处理真实可执行文件的 chcon。

建议先复制一份解包目录试合。看到“验证通过”后再打包，留一条能进 Recovery 的退路。

编译源码
使用 Windows、Python 3.12.10、JDK 17.0.12、Android SDK 35、NDK r27d。仓库已包含 Flex 2.6.4 生成的 lexer C 源码，常规构建不需要再运行 WSL/flex。
先运行 python build_native.py，再运行 python build_apk.py。
JAVA_HOME、ANDROID_HOME 和 ANDROID_NDK_HOME 指定本机工具路径；ROMPOLICY_KEYSTORE 指向已有发布密钥。版本锁和完整 APK 哈希会逐项校验，详见仓库《编译.md》。
构建不会生成替代密钥，也不会连接手机。源码不含签名私钥；自行开发时需使用自己的签名并相应更新发布锁。
源码包含对应 libsepol/secilc 源码、许可证和重链接构建配置；编译后的对象与静态库生成在 build/native。
第三方 libsepol 适用 LGPL 等原许可证；不限制为调试其修改而做的逆向和重新链接。
